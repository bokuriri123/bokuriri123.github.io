💡 Web 知识点：什么是原型污染（Prototype Pollution）

在 JavaScript 中，每个对象都有一个原型（prototype），它是属性查找的 “后备”。当访问某个属性时：

  1. 先看对象自身有没有这个属性；

  2. 没有就沿 ** 原型链（prototype chain）** 逐层往上找；

  3. 找到了就返回，找不到才返回 undefined。

如果一段代码在合并 / 拷贝 / 赋值数据时，没有过滤 __proto__、constructor、prototype 这类特殊键，攻击者就能往 Object.prototype 里 “注入” 属性。而 Object.prototype 是所有对象的公共祖先 ——污染一次，全局所有对象都能 “继承” 到这些属性。

关于密码学

一些密码学 - 加密算法、哈希与认证机制

一、 基础密码学概念

1. 分组与块大小

  • 块大小（Block Size）：128bit / 16字节。现代分组密码算法每次处理固定大小的数据块，数据过长时会被切分成多个块。
  • 注意：在对称加密中，加解密必须使用同一个密钥（Key）。

2. 常见加密算法分类

  • 对称加密：加密和解密使用同一个密钥。
    • **AES (Advanced Encryption Standard)**：高级加密标准，目前最主流、最安全的对称加密算法。
    • DES (Data Encryption Standard)：数据加密标准，已被淘汰，密钥长度太短（56位），极易被暴力破解。
  • 非对称加密：加密和解密使用不同的密钥（公钥和私钥）。
    • RSA：最经典的非对称加密算法。公钥加密，私钥解密（或私钥签名，公钥验签）。不要求加解密双方共享同一个密钥。

二、 分组密码工作模式（Modes of Operation）

当数据大于一个块（16字节）时，需要按照特定模式将各个块串联起来进行加密。

1. CBC (Cipher Block Chaining) 密码分组链接模式

  • 核心流程：
    1. 将一段明文分成 3 块：P1、P2、P3。
    2. P1 与 IV（初始化向量）进行异或（XOR）运算，再进入 AES 引擎加密，生成密文块 C1。
    3. P2 与上一步产生的密文 C1 进行异或（XOR），再进入 AES 引擎加密，生成密文块 C2。
    4. 以此类推，每一块的加密都依赖于前一块的密文，形成链式结构。
  • 优点：相同明文块加密后会得到不同的密文块，安全性高。
  • 缺点：不能并行加密，且如果 IV 可控，可能引发 CBC 字节翻转攻击。

2. 其他常见工作模式

  • CFB (Cipher Feedback) / **OFB (Output Feedback)**：将块密码转换为流密码。
  • **CTR (Counter)**：计数器模式，支持并行加密，效率高。
  • GCM (Galois/Counter Mode)：基于 CTR 模式，同时提供加密和完整性校验（认证），是目前最推荐的模式。

三、 哈希（散列）算法

  • 概念：将任意长度的数据映射为固定长度的散列值。单向、不可逆，主要用于数据完整性校验、密码存储和数字签名。
  • MD5 (Message Digest Algorithm 5)：输出 128 位哈希值，已被证明存在严重的哈希碰撞漏洞，不再安全。
  • **SHA-256 (Secure Hash Algorithm 256)**：输出 256 位哈希值，目前广泛使用，安全性较高。

四、 令牌与认证机制：JWT (JSON Web Token)

1. JWT 基础

  • 特点：JWT 由 Header、Payload、Signature 三部分组成。中间用 . 隔开。
  • 编码方式：使用 Base64URL 编码。

    JWT 使用的是 Base64URL（对 Base64 做了 + 变 -、/ 变 _、去掉 = 的变种），而非标准 Base64。

  • 安全性核心：JWT 的明文部分（Header 和 Payload）可以被任何人解码看到，所以绝对不能存放敏感信息。其安全性完全依赖于签名（Signature），攻击者如果篡改了数据，签名校验就会失败。

2. 签名算法（Signature Algorithms）

JWT 签名主要有两类，原理完全不同：

  • **HMAC-SHA256 (HS256)**：
    • 属于对称加密思想。
    • 服务器和客户端共享一个 Secret（密钥）。
    • 服务端使用这个 Secret 对 Header+Payload 进行哈希计算生成签名。
    • 安全风险：如果 Secret 泄露，攻击者可以伪造任意 JWT。
  • **RSA (RS256)**：
    • 属于非对称加密思想。
    • 服务端持有私钥（Private Key），用来生成签名（加密哈希值）；客户端或验证方持有公钥（Public Key），用来验证签名。
    • 不需要共享 Secret。
    • 安全风险：如果服务端配置不当，允许 HS256 和 RS256 混淆，攻击者可以利用公钥当作 HMAC 的 Secret 进行伪造（著名的 JWT 算法混淆攻击）。

💡 安全面试常见考点提示

  1. JWT 的 alg 字段：常用来指定签名算法，如果后端没有强制校验算法，攻击者可以改成 none 绕过签名。
  2. CBC 字节翻转：在 CBC 模式中，如果攻击者控制了 IV 和密文，修改前一块密文会影响到后一块明文的解密结果（XOR特性），常用于绕过权限验证。
  3. MD5 长度扩展攻击：MD5、SHA1 等基于 Merkle–Damgård 结构的哈希函数存在长度扩展攻击风险。

关于渗透测试

渗透测试入门笔记 - 信息收集篇

一、 基础指纹识别

在拿到目标后，第一步通常是识别目标的基本架构，做到“看菜下饭”。

  • 操作系统：判断是 Windows 还是 Linux，影响后续提权方式和 Payload 的选择。
  • 中间件：查看 HTTP 响应头中的 Server 字段，如：
    • Server: Apache
    • Server: nginx/1.18.0
    • 后续动作：根据组件版本去查对应的 Nday（公开漏洞）或 CVE 漏洞。
  • 脚本信息：判断是 PHP、Java、Python 还是 Node.js，决定后续找哪类漏洞（比如 Java 找反序列化，PHP 找文件包含）。
  • 源代码：获取源码后可以进行白盒代码审计，挖掘 0day。
  • 数据库信息：判断数据库类型（MySQL、MSSQL、Redis等），为后续 SQL 注入或未授权访问做准备。

二、 域名信息收集

这是信息收集的重中之重，用于资产测绘和扩大攻击面。

1. Whois 查询

  • 内容：域名注册人、邮箱、注册时间、过期时间。
  • 作用：用于社工钓鱼，或寻找注册时间久远但疏于维护的老资产。
  • 常用工具：whois 命令、站长工具。

2. DNS 记录

  • A记录：域名对应的 IP 地址。
  • CNAME记录：别名记录，常用于 CDN 识别。
  • 作用：了解目标的网络拓扑，定位真实服务器。

3. 子域名收集

  • 手段：证书透明日志（Certificate Transparency）、字典爆破工具。
  • 常用工具：OneForAll、subfinder、Layer 等。
  • 意义：主站防御严密，边缘子域名往往是突破口（比如 test.xxx.com 或 dev.xxx.com）。

4. 真实 IP（绕过 CDN）

  • CDN（内容分发网络）的作用：加速访问、保护/隐藏真实 IP。
  • 绕过手段：
    • 查看历史 DNS 记录（如 SecurityTrails、DNSdb）。
    • 全球 Ping 测试，寻找未使用 CDN 的节点。
    • 通过 SSL 证书比对。
    • 通过邮件服务器（发信源 IP 大概率是真实 IP）。
    • 敏感信息泄露（如 phpinfo、探针文件）。
  • 实战意义：如果目标套了 CDN，你直接打域名只是在打 CDN 节点，完全无效。必须找到真实 IP 才能发起实质攻击。

5. 旁站查询

  • 概念：同 IP 下的其他网站（即“旁站”）。
  • 思路：如果主站打不进，可以寻找同服务器上防御薄弱的小网站下手，通过拿下旁站，利用服务器内部权限进行横向移动，最终拿下主站。

三、 目录收集

寻找敏感文件泄露，这是最容易出成果的一步。

1. 网站主动暴露

  • robots.txt：爬虫协议，常暴露后台路径或隐藏接口。
  • sitemap.xml：网站地图，了解站点结构。

2. 敏感文件泄露

  • 备份文件：www.zip、web.tar、www.rar 等。
    • 致命点：开发人员安全意识差，将源码打包上传到 Web 根目录，下载后直接白盒审计。
  • 版本控制泄露：.git/、.svn/ 目录。
    • 常用工具：GitHack、dvcs-ripper，直接还原源码。
  • 配置文件：.env、config.php、web.config 等。
    • 致命点：直接泄露数据库账密、云服务 AK/SK，导致服务器沦陷。

3. 目录爆破（依赖字典爆破）

  • 原理：利用常见目录/文件名字典，去猜测网站隐藏路径。
  • 常用工具：dirsearch、gobuster、feroxbuster。
  • 核心：字典的质量决定了爆破的成功率。

🛠️ 渗透信息收集常用工具箱

  • 网络空间测绘：Fofa、Shodan、Quake、Hunter
  • 指纹识别：Wappalyzer（浏览器插件）、whatweb（命令行）
  • 端口扫描：Nmap、Masscan
  • 子域名/目录扫描：OneForAll、dirsearch、gobuster
  • 抓包/改包：Burp Suite、Yakit

MoeCTF 2026「熊出没」题解复盘

MoeCTF 2026「熊出没」题解复盘

一、题目信息

  • 题型：Web / SSRF（100 pts，412 solves）
  • 环境：honey-ssrf-ctf.service
  • 目标：让服务器请求本机 127.0.0.1:54321 获取 flag
  • 干扰：有 WAF（题目里的”捕兽夹/看门狗/假蜜罐”文案），且提示文案随机刷新，不能作为判断依据

二、尝试过程与知识点

第 1 轮：IP 字符串变形（全部失败）

思路：WAF 可能只做字符串匹配，把 127.0.0.1 换成各种等价写法。

失败原因：WAF 不是简单字符串匹配，而是真正解析域名/IP 后判断是否属于内网段（127.0.0.0/8、10/8、172.16/12、192.168/16、::1 等）。

第 2 轮：URL 解析差异（失败）

思路：利用 @ 和 # 让 WAF 和 HTTP 客户端解析出不同的 host。

结果：返回”看门狗”文案——说明 WAF 能正确解析 userinfo 部分，拿到最终 host 是 127.0.0.1 后拦截。

第 3 轮：302 跳转 + DNS Rebinding（失败）

思路：

· 302 跳转：先访问公网 URL（httpbin.org），让它 302 跳转到 127.0.0.1，赌 WAF 不跟踪重定向
· DNS Rebinding：用 rbndr.us 让域名交替解析到公网 IP 和 127.0.0.1，赌 WAF 解析一次、实际请求再解析一次时命中不同 IP

失败原因：WAF 不仅检查初始 URL，还跟随重定向并检查跳转后的 IP；DNS rebinding 也被防住（WAF 与请求端共享 DNS 解析结果，或 TTL 窗口不够）。

第 4 轮：其他冷门绕过（失败）

这些本质上还是”让域名解析到 127.0.0.1”，只要 WAF 做了解析后 IP 检查，全部无效。

三、突破口：换协议（Gopher）

关键思路转变：前面一直在”如何骗过 WAF 对 HTTP host 的检查”上死磕，忽略了 WAF 很可能只对 http:// 和 https:// 协议做内网 IP 过滤，对其他协议不检查。

Gopher 协议原理：

· gopher:// 允许我们构造任意原始 TCP 字节流发送到目标端口
· 下划线 _ 后面就是要发送的原始数据
· 可以用它向 54321 端口”手写”一个完整的 HTTP 请求

原始字符 编码 含义

\r\n %0d%0a HTTP 头换行
_ _ gopher 数据起始标记

五、核心知识点总结

  1. SSRF 防护层级决定绕过手段：
    · 只做字符串匹配 → IP 变形（十进制/十六进制/八进制/nip.io）就能绕
    · 做了解析后 IP 检查 → IP 变形全废，需要 DNS rebinding / 302 跳转
    · 连重定向和 DNS 都防 → 只能换协议
  2. Gopher 协议是 SSRF 的大杀器：
    · 能构造任意 TCP 请求，打 HTTP / Redis / MySQL / FastCGI 等
    · 很多 WAF 只盯着 http://，忽略 gopher:// / dict:// / file://
    · 本题就是典型：WAF 把 HTTP 内网 IP 拦得死死的，但 gopher 直通
  3. 信息泄露：服务器返回的 “paths: /secret-honey” 是解题关键一步，不要只看状态码，要读响应体。
  4. 调试技巧：当所有绕过都失败时，先测 file:///etc/passwd 判断哪些协议放行，比反复试 IP 变形高效得多。
