moectf复盘

查分系统

  • 按 F12 打开开发者工具
  • 使用 Ctrl + U 打开源码
  • 在源码中使用 Ctrl + F 直接搜索 moectf，直接找到了 flag

💡 Web 知识点：F12 是渗透测试的第一步，主要看 Elements（元素）、Console（控制台）和 Network（网络）。Ctrl+U 查看页面源代码往往能发现被隐藏的注释或接口。Ctrl+F 搜索敏感关键字（如 flag、admin、api）是非常高效的找线索方法。

归途

  • 收集信息
  • key1：控制台留下的打印信息（Console 中的 console.log）
  • key2：藏在 HTML 源码里面
  • key3：看网络请求的响应（Network 面板中的 Response）
  • key4：主动写一个请求，直接修改 URL
  • key5：藏在新的请求的标头里面（Request Headers）
  • key6：换成 POST 的请求方式
  • key7：修改 URL，尝试登录，伪造 admin 的 cookie
  • 最后获得提示，去到爬虫协议（Robots 协议）里面找
  • 进入提交界面
  • 进行 Base64 解码

💡 Web 知识点：

  1. HTTP 方法：GET（查）和 POST（改/交）。修改请求方法可以通过 Burp Suite 或者浏览器 F12 的“编辑并重发”来实现。
  2. Cookie 伪造：服务端通常通过 Cookie 中的 session 或身份标识来判断权限，修改 Cookie 可以越权。
  3. Robots 协议：网站根目录下的 robots.txt 是告诉爬虫哪些目录可以爬、哪些不可以。虽然只是“君子协定”，但在 CTF 中常常作为隐藏路径的提示。
  4. Base64 编码：常用于前后端数据传输时的编码混淆，不是加密，可以直接解码。

💡 Web 知识点：

  1. AES-GCM：一种对称加密算法。通常需要两个关键参数：Key（密钥）和 IV（初始化向量）。如果开发者在源码中泄露了 IV，且 Key 是弱口令（如学号），极容易遭受暴力破解。
  2. 爆破攻击：对于有限的密钥空间（例如学号范围），自动化脚本跑字典是最快的方式。

💡 Web 知识点：目录遍历（Path Traversal）。当服务器对用户输入的路径参数没有严格过滤时，可以通过 ../（相对路径）跳出当前目录，访问服务器上的任意文件。例如将 ?file=book1.txt 改为 ?file=../../../../flag 来读取根目录下的敏感文件。

MoeCTF 2026「熊出没」题解复盘

MoeCTF 2026「熊出没」题解复盘

一、题目信息

  • 题型：Web / SSRF（100 pts，412 solves）
  • 环境：honey-ssrf-ctf.service
  • 目标：让服务器请求本机 127.0.0.1:54321 获取 flag
  • 干扰：有 WAF（题目里的”捕兽夹/看门狗/假蜜罐”文案），且提示文案随机刷新，不能作为判断依据

二、尝试过程与知识点

第 1 轮：IP 字符串变形（全部失败）

思路：WAF 可能只做字符串匹配，把 127.0.0.1 换成各种等价写法。

失败原因：WAF 不是简单字符串匹配，而是真正解析域名/IP 后判断是否属于内网段（127.0.0.0/8、10/8、172.16/12、192.168/16、::1 等）。

第 2 轮：URL 解析差异（失败）

思路：利用 @ 和 # 让 WAF 和 HTTP 客户端解析出不同的 host。

结果：返回”看门狗”文案——说明 WAF 能正确解析 userinfo 部分，拿到最终 host 是 127.0.0.1 后拦截。

第 3 轮：302 跳转 + DNS Rebinding（失败）

思路：

· 302 跳转：先访问公网 URL（httpbin.org），让它 302 跳转到 127.0.0.1，赌 WAF 不跟踪重定向
· DNS Rebinding：用 rbndr.us 让域名交替解析到公网 IP 和 127.0.0.1，赌 WAF 解析一次、实际请求再解析一次时命中不同 IP

失败原因：WAF 不仅检查初始 URL，还跟随重定向并检查跳转后的 IP；DNS rebinding 也被防住（WAF 与请求端共享 DNS 解析结果，或 TTL 窗口不够）。

第 4 轮：其他冷门绕过（失败）

这些本质上还是”让域名解析到 127.0.0.1”，只要 WAF 做了解析后 IP 检查，全部无效。

三、突破口：换协议（Gopher）

关键思路转变：前面一直在”如何骗过 WAF 对 HTTP host 的检查”上死磕，忽略了 WAF 很可能只对 http:// 和 https:// 协议做内网 IP 过滤，对其他协议不检查。

Gopher 协议原理：

· gopher:// 允许我们构造任意原始 TCP 字节流发送到目标端口
· 下划线 _ 后面就是要发送的原始数据
· 可以用它向 54321 端口”手写”一个完整的 HTTP 请求

原始字符 编码 含义

\r\n %0d%0a HTTP 头换行

五、核心知识点总结

  1. SSRF 防护层级决定绕过手段：
    · 只做字符串匹配 → IP 变形（十进制/十六进制/八进制/nip.io）就能绕
    · 做了解析后 IP 检查 → IP 变形全废，需要 DNS rebinding / 302 跳转
    · 连重定向和 DNS 都防 → 只能换协议
  2. Gopher 协议是 SSRF 的大杀器：
    · 能构造任意 TCP 请求，打 HTTP / Redis / MySQL / FastCGI 等
    · 很多 WAF 只盯着 http://，忽略 gopher:// / dict:// / file://
    · 本题就是典型：WAF 把 HTTP 内网 IP 拦得死死的，但 gopher 直通
  3. 信息泄露：服务器返回的 “paths: /secret-honey” 是解题关键一步，不要只看状态码，要读响应体。
  4. 调试技巧：当所有绕过都失败时，先测 file:///etc/passwd 判断哪些协议放行，比反复试 IP 变形高效得多。
