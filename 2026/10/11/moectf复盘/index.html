moectf复盘

查分系统

  • 按 F12 打开开发者工具
  • 使用 Ctrl + U 打开源码
  • 在源码中使用 Ctrl + F 直接搜索 moectf，直接找到了 flag

💡 Web 知识点：F12 是渗透测试的第一步，主要看 Elements（元素）、Console（控制台）和 Network（网络）。Ctrl+U 查看页面源代码往往能发现被隐藏的注释或接口。Ctrl+F 搜索敏感关键字（如 flag、admin、api）是非常高效的找线索方法。

归途

  • 收集信息
  • key1：控制台留下的打印信息（Console 中的 console.log）
  • key2：藏在 HTML 源码里面
  • key3：看网络请求的响应（Network 面板中的 Response）
  • key4：主动写一个请求，直接修改 URL
  • key5：藏在新的请求的标头里面（Request Headers）
  • key6：换成 POST 的请求方式
  • key7：修改 URL，尝试登录，伪造 admin 的 cookie
  • 最后获得提示，去到爬虫协议（Robots 协议）里面找
  • 进入提交界面
  • 进行 Base64 解码

💡 Web 知识点：

  1. HTTP 方法：GET（查）和 POST（改/交）。修改请求方法可以通过 Burp Suite 或者浏览器 F12 的“编辑并重发”来实现。
  2. Cookie 伪造：服务端通常通过 Cookie 中的 session 或身份标识来判断权限，修改 Cookie 可以越权。
  3. Robots 协议：网站根目录下的 robots.txt 是告诉爬虫哪些目录可以爬、哪些不可以。虽然只是“君子协定”，但在 CTF 中常常作为隐藏路径的提示。
  4. Base64 编码：常用于前后端数据传输时的编码混淆，不是加密，可以直接解码。

  • 解码后为 moectf2026iv
  • 确定了加密的算法是 AES-GCM
  • 秘钥是学号
  • 之后尝试去爆破
  • 写了一个 Python 代码（AI 制作）
  • 成功爆破

💡 Web 知识点：

  1. AES-GCM：一种对称加密算法。通常需要两个关键参数：Key（密钥）和 IV（初始化向量）。如果开发者在源码中泄露了 IV，且 Key 是弱口令（如学号），极容易遭受暴力破解。
  2. 爆破攻击：对于有限的密钥空间（例如学号范围），自动化脚本跑字典是最快的方式。

古籍翻阅

  • 在给的文件里找到了一个特殊的名字：true_file
  • 随便点开一个书籍，根据 URL 规律，写一个对应的 URL 来访问这个页面
  • 看到提示：“flag 藏在根目录下”
  • 首先尝试直接加 flag，失败
  • 后尝试跳出目录

💡 Web 知识点：目录遍历（Path Traversal）。当服务器对用户输入的路径参数没有严格过滤时，可以通过 ../（相对路径）跳出当前目录，访问服务器上的任意文件。例如将 ?file=book1.txt 改为 ?file=../../../../flag 来读取根目录下的敏感文件。
