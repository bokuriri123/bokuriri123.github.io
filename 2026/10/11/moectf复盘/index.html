查分系统

  • 按 F12 打开开发者工具
  • 使用 Ctrl + U 打开源码
  • 在源码中使用 Ctrl + F 直接搜索 moectf，直接找到了 flag

💡 Web 知识点：F12 是渗透测试的第一步，主要看 Elements（元素）、Console（控制台）和 Network（网络）。Ctrl+U 查看页面源代码往往能发现被隐藏的注释或接口。Ctrl+F 搜索敏感关键字（如 flag、admin、api）是非常高效的找线索方法。

归途

  • 收集信息
  • key1：控制台留下的打印信息（Console 中的 console.log）
  • key2：藏在 HTML 源码里面
  • key3：看网络请求的响应（Network 面板中的 Response）
  • key4：主动写一个请求，直接修改 URL
  • key5：藏在新的请求的标头里面（Request Headers）
  • key6：换成 POST 的请求方式
  • key7：修改 URL，尝试登录，伪造 admin 的 cookie
  • 最后获得提示，去到爬虫协议（Robots 协议）里面找
  • 进入提交界面
  • 进行 Base64 解码

💡 Web 知识点：

  1. HTTP 方法：GET（查）和 POST（改/交）。修改请求方法可以通过 Burp Suite 或者浏览器 F12 的“编辑并重发”来实现。
  2. Cookie 伪造：服务端通常通过 Cookie 中的 session 或身份标识来判断权限，修改 Cookie 可以越权。
  3. Robots 协议：网站根目录下的 robots.txt 是告诉爬虫哪些目录可以爬、哪些不可以。虽然只是“君子协定”，但在 CTF 中常常作为隐藏路径的提示。
  4. Base64 编码：常用于前后端数据传输时的编码混淆，不是加密，可以直接解码。

七狗免费小说

  • 找到了PHP的源码之后发现黑名单
  • 排除所有被 ban 的经典伪协议
    1. file:// → 含file，ban
  1. data:// → 含data，ban
  2. php://input → 含input，ban
  3. php://env → 含env，ban
  4. ../目录穿越 → 含..，ban
  5. convert.base64-encode过滤器 → 里面有convert关键词，ban
  6. string.rot13过滤器 → 里面有string关键词，ban

✅ 剩下唯一可用大类：php://filter
php://filter 这个字符串里，没有任何黑名单关键词！ 不会触发die("咬你哦！")

  • 看业务逻辑，理解包含之后发生了什么
  • 拆解规则：
  1. include($file)：文件包含，如果是普通 php 文件，会执行代码；如果是 php://filter 伪协议，只会读取文件原始字节，不执行代码（这正是我们想要的！）
  2. preg_match('//u', $output)：检测输出是不是合法 UTF-8 文本
    • UTF8 文本：直接明文输出
    • 二进制数据：走 else 分支，自动 base64 输出

注释提示：小刻不知道什么是二进制流，但是小刻觉得这里的代码古怪
提示就是告诉：要制造二进制输出，让程序帮我们 base64 打包返回

  • 选 zlib.deflate

php://filter 可以加载多种过滤器：

  • convert.*：被 ban
  • string.*：被 ban
    剩下的：zlib.deflate，zlib 压缩过滤器
  1. zlib.deflate 读取文件源码 → 压缩成二进制字节流
  2. 二进制不是合法 UTF8 → 命中 else 分支，服务器自动base64_encode返回给浏览器
  3. zlib这个词，不在黑名单里面，不会触发咬你哦！

在剩下可用的过滤器里挑符合条件的。

  • 构造 payload

  • 逻辑闭环：
    php://filter（过黑名单） + zlib.deflate（产生二进制，触发 base64 分支） + resource=flag.php（目标文件）

  • 最后解码解压得到的一串base64编码数据

    注意使用raw inflate 而不是zlib inflate解压

💡 Web 知识点：
所有同类型都按这个顺序分析：

  1. 拿到源码（一般通过highlight_file(__FILE__)、报错、源码泄露）
  2. 提取黑名单 / 白名单正则，把被禁用的关键词全部划掉，排除所有被 ban 的伪协议
  3. 看include/require的前后代码：有没有缓冲区 ob、有没有输出过滤、有没有编码判断（像本题的//u）
  4. 在剩下没被 ban 的伪协议里，选符合代码逻辑的 payload
  5. 测试 payload，拿到回显，解码

payload 不是固定不变的

  • 有的题黑名单不一样，可能 zlib 被 ban，就要换别的过滤器（iconv 等）
  • 有的题没有ob_start，没有 UTF8 判断，直接用convert.base64-encode
  • 有的题允许../，直接目录穿越读文件，根本不需要伪协议

💡 Web 知识点：什么是原型污染（Prototype Pollution）

在 JavaScript 中，每个对象都有一个原型（prototype），它是属性查找的 “后备”。当访问某个属性时：

  1. 先看对象自身有没有这个属性；

  2. 没有就沿 ** 原型链（prototype chain）** 逐层往上找；

  3. 找到了就返回，找不到才返回 undefined。

如果一段代码在合并 / 拷贝 / 赋值数据时，没有过滤 __proto__、constructor、prototype 这类特殊键，攻击者就能往 Object.prototype 里 “注入” 属性。而 Object.prototype 是所有对象的公共祖先 ——污染一次，全局所有对象都能 “继承” 到这些属性。
